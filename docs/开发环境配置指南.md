# 微信支付开发环境配置指南

## 1. 概述

为了方便开发和测试，我们实现了一套完整的微信支付模拟机制，使开发人员能够在没有实际微信支付证书和密钥的情况下进行开发和测试。本文档详细说明了这套模拟机制的工作原理和配置方法。

## 2. 模拟机制原理

### 2.1 模拟触发条件

系统会在以下情况下自动启用模拟机制：

1. 商户私钥文件不存在
2. 证书序列号未配置
3. API V3密钥未配置

### 2.2 模拟实现方式

当触发模拟条件时，系统会：

1. 创建一个模拟的HttpClient，替代实际的微信支付HttpClient
2. 拦截所有微信支付API请求
3. 返回预定义的成功响应
4. 更新相关订单状态，模拟完整的支付流程

## 3. 开发环境配置

### 3.1 基本配置

在`application-dev.yml`中配置以下参数：

```yaml
wx:
  pay:
    appId: 你的测试小程序appId（可以是虚构的）
    mchId: 1234567890（可以是虚构的）
    mchKey: 32位随机字符串（可以是虚构的）
    notifyUrl: http://localhost:8080/api/pay/notify
    refundNotifyUrl: http://localhost:8080/api/pay/refund/notify
    signType: HMAC-SHA256
    # 以下三项不配置或配置为空，将触发模拟机制
    apiV3Key: 
    privateKeyPath: cert/apiclient_key.pem
    certSerialNo: 
```

### 3.2 模拟支持的功能

当前模拟机制支持以下微信支付功能：

1. 创建支付订单（统一下单）
2. 查询支付订单
3. 关闭支付订单
4. 申请退款
5. 查询退款订单

### 3.3 模拟响应数据

模拟机制会生成符合微信支付API规范的响应数据，包括：

- 正确的返回码和返回信息
- 符合规则的订单号和交易号
- 正确的签名（使用MOCK_SIGN占位）
- 必要的业务参数

## 4. 测试方法

### 4.1 测试支付流程

1. 创建订单
2. 调用支付接口，获取支付参数
3. 查询支付订单（模拟会返回支付成功）
4. 验证订单状态是否更新

### 4.2 测试退款流程

1. 创建已支付的订单
2. 申请退款
3. 查询退款订单（模拟会返回退款成功）
4. 验证退款订单状态是否更新

## 5. 切换到生产环境

当需要切换到生产环境时，需要：

1. 申请真实的微信支付商户号
2. 下载API证书，放置在指定目录
3. 配置实际的商户私钥路径
4. 配置实际的证书序列号
5. 配置实际的API V3密钥
6. 配置可外网访问的通知URL

## 6. 注意事项

1. 模拟机制仅适用于开发和测试环境，不应在生产环境中使用
2. 模拟数据仅模拟成功场景，不模拟各种失败场景
3. 模拟机制会在日志中输出相关信息，方便调试
4. 模拟机制会更新数据库中的订单状态，与实际支付流程保持一致

## 7. 常见问题

### 7.1 如何确认模拟机制是否生效？

查看应用启动日志，如果包含以下信息，则表示模拟机制已生效：
```
微信支付私钥文件不存在：cert/apiclient_key.pem，将使用模拟的HttpClient
```

### 7.2 如何测试支付失败场景？

当前模拟机制不支持自动测试失败场景。如需测试，可以修改相关代码，手动模拟失败响应。

### 7.3 模拟环境下的数据安全性

模拟环境下不会发送实际请求到微信支付服务器，所有数据都在本地处理，不存在数据泄露风险。
